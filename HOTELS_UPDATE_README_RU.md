# Обновление вкладки «Отели» — 9 ноября 2026

## Установка

ZIP содержит только изменённые/новые файлы. Распакуйте его в корень репозитория kepler-ios-main с заменой, сохранив каталоги Sources и Backend. Не заменяйте весь репозиторий содержимым патча.

1. Обновите сервер Backend/PackageEngine через существующий workflow Deploy iumrah Package Engine. Он должен использовать обновлённый wrangler.template.jsonc. Добавлен cron `23 * * * *` для постепенного прогрева статических фотографий; ежедневный `0 3 * * *` сохранён.
2. На Worker должны быть существующие HOTELS_DB и секрет NUITEE_API_KEY. Ключ в ZIP не добавлен. Новая SQL-миграция не нужна: используется nuitee_hotel_cache, создаваемая существующим адаптером.
3. Соберите iOS обычным workflow/Xcode и проверьте на iPhone светлую/тёмную тему, переключение городов, раскрытие/сворачивание поиска и прокрутку хедера.

Сервер и приложение не были развёрнуты из этой сессии. Архив содержит исходники, не IPA.

## Что изменено

- Компактный свёрнутый поиск по умолчанию; кнопка поиска сворачивает форму и применяет параметры.
- Убран отступ -40, из-за которого форма перекрывала верхний переключатель.
- Мекка/Медина вынесены над поиском. Убрана вторая форма поиска внутри результатов.
- Каталог открывается сразу. Статические карточки загружаются отдельно от цен, поэтому сбой цен не удаляет каталог.
- Хедер вкладки «Отели» продолжается под системную область и прокручивается вместе с ней. Отдельная постоянная чёрная подложка этой вкладки удалена; остальные вкладки сохраняют прежнюю геометрию.
- Поисковая карточка использует согласованную светлую палитру; списки и информационные карточки — адаптивные поверхности.
- Убраны вызовы detail API для каждой карточки при прокрутке. Полная информация запрашивается при открытии отеля.

## Nuitee: установленное и неизвестное

По исходникам подтверждено: адаптер превращал любое поле `error` в NUITEE_PROVIDER_ERROR, не различая отсутствие доступности и технический сбой. HTTP-ошибки теряли внутренний код поставщика. Каталог уже кэшировался на 150 отелей каждого города, а минимальные цены сохранялись на 48 часов. Просмотр карточек дополнительно запрашивал фотографии через detail API.

Без production-логов нельзя установить, какие ответы получили именно те пять отелей на вашем аккаунте. Отсутствие тарифа не доказывает превышения лимита. Корректные цены для каждого отеля и любых дат поставщик не гарантирует.

Теперь учитываются:

- `2001`: нет доступного тарифа; это не общий сбой API.
- HTTP 429 / код `4290`: лимит; Retry-After сохраняется в D1 (1–3600 секунд, по умолчанию 60), последующие обращения в этот период не вызывают поставщика.
- `4011`: таймаут/сбой поставщика; отдельная причина.
- HTTP 401/403, остальные числовые коды, сетевой таймаут и некорректный ответ различаются.

В Cloudflare Worker Logs фильтруйте event `nuitee_request`. Поля: path, status, supplierCode, durationMs, returned. Ключи, тела запросов и данные гостей в эти записи не попадают. Показатель returned отражает число вернувшихся тарифов, а не число ошибок отелей.

## Кэш и фотографии

- До 150 реальных отелей на город в D1, срок статических данных 7 дней, при сбое используется сохранённый каталог.
- В D1 сохраняются URL обложек и галерей. Фоновый прогрев ограничен четырьмя запросами detail на город за запуск, выполняется постепенно, без массовой загрузки 300 отелей при открытии экрана.
- Бинарные фотографии сохраняются существующим дисковым кэшем iOS после просмотра. Это не серверное зеркало всех изображений: если CDN поставщика недоступен, на новом устройстве ещё не загруженные фото могут отсутствовать.
- Цены получают одним пакетным min-rates запросом. Одинаковые одновременные запросы объединяются внутри Worker isolate; между isolates действует общий кэш и cooldown в D1, но глобальной блокировки всех запросов нет.
- Кэш цены: город, даты, взрослые, гражданство UZ и валюта USD; 15 минут, для пустой доступности 2 минуты. Старый 48-часовой кэш цен не используется.
- При техническом сбое допускается помеченная устаревшая цена только для тех же параметров и не старше 6 часов. При открытии отеля тарифы проверяются отдельно; старые предложения не превращаются в подтверждённую бронь.
- Многокомнатные и семейные запросы продолжают использовать существующий сценарий ручного подтверждения; взрослый тариф им не подставляется.

## Проверки

- TypeScript проверка типов — успешно.
- Runtime suite — 34/34, включая 6 новых сценариев: независимый статический каталог, 2001, 429/cooldown, объединение запросов и изоляция параметров, ограничение устаревших цен, кэш 150 отелей с URL фото.
- Точечные контрактные тесты отелей/перелётов — 12/12.
- Общий статический набор — 140/145; те же пять ошибок воспроизведены на исходном архиве: carousel comparison, generator-production-pricing, синхронизация локали виджетов, локализация booking labels, passwordless-entry.
- Xcode/iOS Simulator отсутствуют в окружении: сборка SwiftUI, визуальная проверка статус-бара и тест на устройстве не выполнялись. Production Nuitee и его квота не проверялись.
