# iumrah Intelligence — iOS → iumrah-backend → iumrah Business

## Установка

1. Загрузить `iumrah-beta-update-20261110-intelligence-v1.zip` в **корень** клиентского GitHub-репозитория `kepler-ios-main` (`main`). Не распаковывать вручную.
2. Дождаться `Actions → Apply iumrah Beta ZIP update` (архив будет извлечён и удалён автоматически).
3. Запустить существующий `Actions → Iumrah | TestFlight | Intel | New Team` с нужным `release_version` и установить новую клиентскую сборку.
4. Открыть клиентское приложение, пройти несколько экранов, выполнить поиск рейсов или отелей. Через несколько секунд после события клиент отправляет пакет в `iumrah-backend`.
5. В iumrah Business открыть «Аналитика» → обзор/сессии. Если данных нет, проверить статус API и D1-таблицы `intelligence_events`, `intelligence_reports` в **существующей** базе `iumrah-hotels`.

Новых GitHub Secrets, Workers или баз не требуется. **Повторный деплой backend не нужен**, если `iumrah-backend` из актуального Business-репозитория уже успешно опубликован и миграция `0044_business_intelligence.sql` выполнена. Gemini API Key остаётся на сервере, не в клиенте.

## Схема и маршрут

Публичный ingest: `POST https://iumrah-backend.helloiumrah.workers.dev/api/catalog/hotels/intelligence/events`

Контракт: `visitorId` (случайный UUIDv4 на установку), `sessionId` (UUIDv4 на foreground-сессию), `platform=ios`, `appVersion`, `events` (не более 20 в одном запросе). `name`, `screen` и `elementId` — заранее заданные коды, НЕ тексты полей, имена, номера брони или платежей. Повторно отправленные события сервер дедуплицирует по UUID событий.

Отслеживаемые места:
- `app_first_open`, `app_open`, `app_background`; просмотр и длительность экранов (пять вкладок, онбординг, конфигуратор рейсов, каталог авиабилетов, карточка отеля, checkout);
- пять **фактически имеющихся в этом ZIP** экранов онбординга, пропуск, завершение;
- запуск поиска, наличие/отсутствие результатов, выбор исходящего/обратного рейса, просмотр карточки отеля, выбор тарифа;
- просмотр цены на checkout, начало оформления, отправленную заявку на бронь и ошибки отправки;
- CTA главной страницы: поиск поездки, открытие рейсов и отелей.

`booking_submitted` = заявка создана, **не** успешная оплата. `booking_completed` намеренно НЕ генерируется при создании заявки: это было бы неверной метрикой выручки.

Технически невозможно надёжно отследить удаление iOS-приложения конкретным человеком. `app_background` отражает переход в фон, не обязательно принудительное закрытие или удаление.

## Доступность и приватность

- «Аккаунт → Настройки → Аналитика использования» доступен гостю и авторизованному пользователю. Переключатель выключает отправку и очищает очередь/локальный псевдонимный идентификатор; его статус сохраняется.
- Никакой автоматической записи всех касаний экрана, содержимого полей, переписки, паспортов, платежей, рекламных идентификаторов, геолокации или скриншотов.
- Очередь до 150 событий, не более 6 суток локально; хранится в контейнере приложения. При потере сети не блокирует UI и повторяет отправку при новой активности.
- Прежде чем выпускать сборку публично, проверить актуальность **Privacy Policy** и декларации **App Privacy** в App Store Connect (псевдонимные идентификаторы и product interactions). Это собственная аналитика продукта, не межсайтовое рекламное отслеживание.

## Тесты

На машине со Swift 5+ (в том числе Linux):

```
swiftc -typecheck Sources/Services/IumrahIntelligence.swift
scripts/test-intelligence-contract.sh
python3 scripts/ci_preflight.py
```

Smoke-тест проверяет формирование событий, временные отметки, очередь и удаление локальных данных при выключении. Проведена дополнительная проверка с реальной `validateIntelligenceBatch` из Backend/HotelsWorker: 10 из 10 синтетических событий приняты. На Linux не выполняется полноценная компиляция SwiftUI/iOS: её нужно выполнить через Xcode GitHub Actions.

## Не входит в это обновление

- Не меняется `AppConfig.apiBaseURL` (`https://iumrah.app`) для существующей авторизации и оплаты: единый backend пока не содержит все старые маршруты `/api/bookings` и `/api/package`. Принудительное переключение всего API сломало бы приложение.
- Не затрагивается Android, не включено бесконтрольное логирование всех кнопок, нет достоверной статистики персональных удалений или атрибуции установок App Store без отдельной интеграции данных магазина.
- Firebase, сторонние SDK, ключи на клиенте и новые базы не добавлены.
