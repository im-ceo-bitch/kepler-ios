# iumrah Personal Guide — iOS update (2026-11-25)

Base: kepler-ios-main 5.zip. Companion backend/business update: iumrah-business-20261125-personal-guides.zip. Deploy the Business backend first; existing `/api/catalog/hotels/team` remains compatible with old apps. The new iOS screen can load public team profiles without sign-in. It uses the existing header, search surface, image cache, date controls, colors and package models. The home and lower tab bar have not been redesigned.

- Navigation: existing discovery pills → Guides after Transfer; details and selection sheet, dates and scope, real employee profile from live public team API, six-stage accompaniment program, clear pricing and extra-cost terms, automatic or specific selection.
- Manual package: guide preference appears in My package and flows into the shared final review. The official/guided and Smart configurators can select or change the guide in their shared FinalPackageView. Existing draft restoration includes the optional guide preference.
- Booking/saved package: stable member ID is sent in `booking.customization.preferredGuideID`; old clients and auto-selection omit it. Accompaniment pricing remains server-owned. Choosing a person is not a confirmed assignment.
- Catalog is RU/EN/UZ/UZ-Cyrl; other app languages use the existing English fallback. Profile biography and languages are live data, not machine-translated or invented. Intro video plays a real HTTPS media URL if supplied. Review UI renders only a supplied public guide-review feed; the provided backend has no consented guide-specific review source and does not publish private trip feedback.
- Availability uses existing explicit booking assignments; no unrecorded days-off calendar is inferred. Status is requestable, not confirmed. Existing package pricing is shown only when a real quote is available.

QA: Swift frontend syntax parsing of changed files performed on Linux. Full Xcode/iOS SDK typecheck, TestFlight build, visual simulator/device QA, and real production API verification were not possible in this environment. Run the existing TestFlight workflow and check on iPhone mini + a larger iPhone before production. Test sequence: Guides → real public profiles → choose → My package → final summary → save/restore → booking → Business preferred guide → confirm assignment. Repeat for Smart/official review and choose-auto. Test dates that overlap a confirmed assignment, no-network, hidden profiles, dark mode and larger Dynamic Type. No workflow, signing or main dashboard changes.
