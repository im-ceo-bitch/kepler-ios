# iumrah — Premium Flight Detail

Патч для kepler-ios-main 9. Накопительный с IumrahHemisphereMap. Распаковать в корень существующего репозитория. Не заменяет репозиторий целиком, не меняет workflows, cron, идентификаторы и логику бронирования. Общий SwiftUI-экран используется в деталях поиска, Flight First, конфигураторе и деталях бронирования. Старые списки могут по-прежнему открывать детали отдельной кнопкой.

## AeroDataBox
В предоставленных исходниках не найден существующий клиент AeroDataBox. Добавлен read-only GET `/api/package/flights/detail` в действующий Package Engine (`iumrah-package-api`), использующий текущую D1 binding HOTELS_DB. Не создаётся новый Worker или база. Используется официальный RapidAPI-host AeroDataBox, поиск по номеру/локальной дате вылета; результат дополнительно сопоставляется по аэропортам и минуте расписания. Альтернативный прямой AeroDataBox endpoint не настроен. Если подключение в другом Worker, проверьте его до активации, чтобы не дублировать расходы.

В Cloudflare Dashboard → Workers & Pages → iumrah-package-api → Settings → Variables and Secrets добавьте секрет `AERODATABOX_RAPIDAPI_KEY` (существующий ключ RapidAPI) и `AERODATABOX_DAILY_REQUEST_LIMIT` (целое положительное число, которое соответствует вашему тарифу и допустимому бюджету). Без обоих параметров обогащение отключено; UI работает на исходных данных. Ключ не включается в iOS/ZIP/ответ API. Счётчик D1 создаётся автоматически при первом включённом запросе; отдельной миграции не требуется. Лимит — суммарный по UTC-дню, учитывает попытки, а не только успешные вызовы. Рекомендуется дополнительно установить Cloudflare rate limiting для данного публичного endpoint перед запуском на большой аудитории. Не публиковать ключи в GitHub или чате. Нет фонового polling; при открытии экрана — запрос, затем ручное обновление при наличии результата. Повторные одновременные одинаковые запросы одного приложения объединяются.

Сначала Deploy iumrah Package Engine, потом TestFlight. Без изменения серверной части возможен только базовый UI без нового enrichment endpoint. Цена и багаж остаются данными текущего поставщика/офера; AeroDataBox не поставляет условия конкретного тарифа. Маршрут — большая окружность, не реальный трек полёта. Зелёный прогресс оценивается по свежим координатам (до 15 мин), точка самолёта — предоставленные координаты. Нет симуляции статуса или телеметрии. Карта — полная видимая сфера, чтобы показать весь маршрут. Локальные времена известных аэропортов пересчитываются по часовым поясам; если часовой пояс неизвестен, сомнительное время не отображается как локальное. Четыре основных языка, английский fallback для остальных.
