# V7 — исправление выбора рейсов и переходов конфигуратора

Накопительное обновление на основе V6 из этого чата. Файлов .github/workflows нет.
Если после V6 вы меняли эти же файлы другими обновлениями, сначала объедините изменения: этот архив основан на доступной здесь версии, а не на текущем GitHub.

Изменения:
- Отдельная круглая кнопка выбора справа сверху карточки рейса. Тело карточки по-прежнему открывает детали. Выбор активирует переход к обратному рейсу; переключатель также доступен. Повторный выбор того же рейса не сбрасывает выбранный обратный.
- После выбора комнаты и закрытия деталей переход к следующей незаполненной комнате текущего города, затем к следующему городу. Когда все комнаты выбраны — автоматическое открытие трансфера. Возврат назад без выбора ничего не переключает.
- Подтверждение трансфера ведёт сразу к существующему итоговому экрану после успешного серверного расчёта. Ошибки расчёта не обходятся поддельной ценой.
- Обычный маршрут туда-обратно отправляет совместимый 10-компонентный Aviasales ID. Маршрут с разными аэропортами прилёта/вылета сохраняет 12-компонентный ID и требует включённый backend из V6/V7.
- Понятное сообщение об ошибке маршрута на RU, EN, UZ Latin, UZ Cyrillic вместо голого технического кода.

Причина на скриншоте: AVIASALES_IDENTITY_INVALID означает отказ парсера идентификатора, а не отсутствие цены. В исходном backend было строго 10 компонентов, клиент V6 отправлял 12 для каждой пары. Такая несовместимость воспроизводима по коду; версия работающего сервера и конкретный запрос пользователя не получены.

Установка: распаковать штатным распаковщиком. Обновить сервер, обслуживающий /api/package/quote, затем собрать iOS. Одной сборки iOS недостаточно для маршрута TAS→JED / MED→TAS на старом сервере. Workflow не изменены. Если backend уже перенесён в отдельный iumrah-backend, изменения нужно перенести именно в его обработчик — деплой другого Worker проблему не исправит.

Проверено: TypeScript и 49 runtime-тестов проходят, в том числе оба формата ID, open-jaw маршрут и отклонение некорректного ID. Синтаксический разбор пяти изменённых Swift-файлов проходит. Xcode, переходы на реальном iPhone и живое бронирование здесь не запускались.

Остаются ограничения V6: sandbox Nuitee не разрешает реальную бронь; реализация канонического /api/bookings отсутствует в этом репозитории; пять ранее выявленных ошибок полного набора контрактных проверок не исправлены этим обновлением. Runtime-проверки не заменяют полный npm test, проверки не отключались.
