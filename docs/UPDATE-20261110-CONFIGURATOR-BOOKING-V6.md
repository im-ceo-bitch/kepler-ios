# iumrah V6 — основной конфигуратор и бронирование

Накопительный патч поверх исходного kepler-ios-main-5; включает изменения V5.

## Подключение
- Основной конфигуратор использует LegacyFinalPackageView — тот же итоговый экран, что Hotel First / Flight First.
- Вместо LocalJourneyRequestView и отправки в iumrah Care используется IumrahBookingConfirmationView с существующим SMS/email OTP, затем BookingStore.create и существующий /api/bookings.
- Номер брони и Umrah ID не генерируются новым кодом: используется текущая серверная цепочка создания, привязки подтверждённого контакта и синхронизации Business.
- Точный список выбранных номеров, дат, гостей и offerId передаётся в generatorTrace и серверный зашифрованный отчёт. prebookId сохраняется только в серверном отчёте.
- Клиентская формула суммы удалена. PackageEngine рассчитывает пакет существующим calculatePackageQuote; цены виз, трансферов, гида, питания, наценки и комиссии не менялись.
- Категории: 1–2★ Economy, 3–4★ Standard, 5★ Luxury. Звёздность проверяется по серверному каталогу. При разных категориях двух городов применяется более высокая. Неизвестная звёздность не подменяется выбранной на клиенте категорией.
- Один отель на город соответствует существующей модели бронирования. При смене отеля сбрасываются номера этого города; все выбранные номера отображаются в итоге.
- Выбранные Nuitee offerId проверяются через официальный PREBOOK, а не повторным поиском с новыми offerId. Цена, валюта, отель, даты, гости и изменения условий проверяются. Карта или списание денег не вызываются.
- Бронирование повторно проверяет сумму после OTP. При изменении цены требуется вернуться к итогу и проверить новую сумму. Уже полученная серверная бронь повторно не создаётся при повторе операции подтверждения контакта.
- Исправлена идентификация двух раздельных рейсов с разными аэропортами прилёта/обратного вылета (например TAS→JED и MED→TAS).
- Новые сообщения — RU, EN, UZ Latin, UZ Cyrillic.

## Что проверено
- Серверные runtime-тесты: 47/47, включая категории, PREBOOK, игнорирование подставленной цены, sandbox, истёкшие/чужие offerId, изменение условий, несколько номеров, серверный расчёт и зашифрованный отчёт.
- TypeScript прошёл проверку компиляции в runtime-наборе.
- Изменённые Swift-файлы прошли синтаксический разбор; полноценной сборки с iOS SDK не было.
- Полный старый набор контрактов: 140/145. Сохранились пять ранее существовавших ошибок: carousel comparison, generator-production-pricing, widget locale, hardcoded booking labels, passwordless entry. Эти проверки не отключались; стандартный npm test и вызывающий его deploy остаются заблокированы до исправления этих отдельных ошибок.

## Важные границы
- Это подключение к реальной записи бронирования iumrah и существующему процессу подтверждения, не автоматическая покупка билета и не оплаченная бронь поставщика. /rates/book и платежи поставщику не вызываются — сохранён текущий процесс оформления iumrah.
- Последняя проверка развёрнутого Nuitee API показывала sandbox=true. Тестовый ключ sand_ не позволяет оформить реальную бронь в новом пути; нужен production NUITEE_API_KEY. Тестовые цены остаются видимыми с заблокированным оформлением.
- Data API не подтверждает отдельные тарифы детей и младенцев: их нельзя считать как взрослые. Для такой группы требуется опубликованный рейс с тарифом группы или полноценный источник пассажирских тарифов.
- Сам канонический обработчик /api/bookings находится вне предоставленного PackageEngine. Патч использует тот же клиент и контракт, что рабочие Hotel First / Flight First; end-to-end создание записи в production и отображение в Business здесь не проверялись.
- Реальные SMS/email и реальные записи бронирований в этой среде не создавались. Xcode/TestFlight не запускались.

## Установка
1. Загрузить iumrah-beta-update-20261110-configurator-booking-v6.zip в корень репозитория и применить существующим распаковщиком. В ZIP пути от корня, без лишней папки.
2. Нужны обе части: PackageEngine и iOS. Не выпускать только клиент с прежним сервером: прежний /quote не понимает nuiteeRooms.
3. Перед production-деплоем устранить перечисленные существующие ошибки полного npm test; проверки намеренно не обходятся.
4. Запустить Deploy iumrah Package Engine, затем Iumrah | TestFlight | Intel | New Team.
5. На тестовой среде проверить 1/2/3/4/5★, два города, несколько номеров, истечение offerId, изменение цены, SMS и email, повтор отправки, единый booking number / Umrah ID и появление записи в Business.

Официальная документация проверки тарифа: https://docs.liteapi.travel/reference/post_rates-prebook
