# Обновление 12 ноября — конфигуратор, питание и бронирование

Патч для актуального kepler-ios-main.zip, присланного 12 ноября. Только изменённые файлы. Старые накопительные ZIP поверх этого обновления не накладывать. Файлов .github/workflows, секретов, базы и node_modules внутри нет.

Установка: загрузить ZIP в корень репозитория и распаковать штатным workflow. Затем новый Run workflow для Deploy iumrah Package Engine на последнем коммите, затем собрать TestFlight. Если маршрут /api/package/quote обслуживается другим Worker, эти backend-изменения должны попасть именно в него.

Изменения:
- Выбор галочкой рейса туда автоматически открывает обратные рейсы и переключатель, выбор обратного — отели. Нажатие на карточку сохраняет открытие деталей. Выбор из деталей продолжает маршрут после закрытия деталей.
- Следующий город/номер открывается с начала списка отелей. После всех номеров открывается трансфер, после его подтверждения — итог.
- Итог: компактные строки услуг, одна карточка на номер, явное «Изменить номер», выделенные даты и ночи, питание отдельно для каждого номера. Окно изменения номера открывается на всю высоту с закрытием. Заблокированная кнопка получает пояснение и отличается визуально.
- Завтрак 4–5★ включён за счёт пакета iumrah, если не включён поставщиком. Питание, включённое в тариф API, не начисляется повторно. В Мекке доступны завтрак/обед/ужин, в Медине завтрак/ужин. Дополнения добровольные, расчёт на сервере за ночи и гостей конкретного номера. Используются существующие единичные ставки движка ($15 Economy/Standard, $30 Comfort, $50 Luxury); ставка определяется категорией отеля соответствующего города. Новые цены не придуманы.
- Economy/Standard: зияраты остаются в пакете и в отчёте отдельными строками с $0. Comfort/Luxury сохраняют существующую цену. Версия расчёта v10.
- Sandbox: разрешена внутренняя бронь iumrah по цене, ранее полученной сервером из Sandbox. Нельзя подставить цену с телефона. В отчёте сохранены supplierMode=sandbox и supplierReservationConfirmed=false; гостиничные строки помечены Sandbox. Это НЕ подтверждение номера у поставщика и НЕ выписка авиабилетов.
- Удобства отеля и номера: общие названия переводятся без внешнего ключа на RU/UZ/UZ-Cyr; для остальных действует существующий перевод API. Неизвестные названия без перевода сохраняются, а не заменяются выдуманными. Кэш описаний обновлён.
- Исправлены падения проверок: разбиты тяжёлые SwiftUI-поддеревья бронирований, восстановлена Orbit в карточке конфигуратора, локализация номера брони и синхронизация языка виджетов. Оставшиеся парольные поля входа/регистрации заменены существующим email/SMS OTP. Проверки итоговой страницы актуализированы под текущую страницу; проверки не отключены.

Business: существующий механизм передаёт серверный ценовой отчёт после авторизованного создания брони. При существующей поездке отчёт записывается в pilgrim_trips.pricing_snapshot_json; иначе — в pending_package_pricing_reports с booking_id. Проверены обе ветки, сохранение питания, нулевых зияратов и sandbox-источника, отказ при неверном токене. Показ отчёта в живом приложении Business и реальное создание брони в вашей базе в этой среде не проверялись; сам Business в этом архиве не изменялся.

Проверено: npm run typecheck; полный npm test — 148 контрактных + 55 runtime тестов; синтаксический разбор изменённых Swift-файлов; целостность ZIP. Xcode/симулятор/iPhone в среде недоступны: успешная компиляция и визуальный результат на устройстве здесь не подтверждены.
