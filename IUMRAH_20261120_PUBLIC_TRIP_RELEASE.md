# IUMRAH — синхронизация iOS / веб и публичный просмотр поездок

Дата: 20 ноября 2026. Патчи предназначены для **двух разных репозиториев** и устанавливаются отдельно.

## Блок 1. iOS как эталон
- Исследованы `HotelsHomeView`, `NuiteeCatalogModel`, `NuiteeHotelDetailView`, `SmartConfiguratorFlow`, `IumrahManualJourneyStore`, `FinalPackageView`.
- iOS: добавлены операции создания/отзыва публичных ссылок; для владельца допускаются токен брони **или** подтверждённая сессия аккаунта. Обработчик `/s/{token}` открывает в приложении тот же защищённый read-only веб-экран.
- Поддержаны `/flights/package/{id}` и `/s/{token}` в веб AASA; сохранены гостиничные маршруты.

## Блок 2. Веб-каталог и конфигураторы
- Веб: переключение заголовков «Отели» / «Авиабилеты» с увеличением активного заголовка; единый каталог рейсов и отелей использует существующие API без подмены цен.
- Веб: официальное начало `/generator`, ручное `/manual` (маршрут запуска `/generator?mode=manual`) и Smart `/smart` с подбором **только опубликованных прямых рейсов**. Smart отсекает варианты с пересадками и просроченные даты, показывает номер обратного рейса. Выбор Smart попадает в общий генератор, где реальный маршрут/цена перепроверяются.
- Главная: адаптированы три карточки методов организации умры под текущую крупную фирменную веб-типографику без замены анимации поиска и других секций.
- Вкладка «Мои поездки» сохранена без обязательного входа в аккаунт; не подменяет рабочую зону конкретного бронирования.

## Блок 3. Публичная ссылка и безопасность
- `POST /api/package/booking/{bookingId}/share`: только владелец, создание одноразового случайного токена доступа **только к просмотру**.
- `GET /api/package/shares/{shareToken}`: отдаёт whitelist сведений о маршруте, рейсах, отелях, услугах и документальных статусах. Не отдаёт ФИО, паспорт, номер визы, сам документ, PNR, QR билета, секрет брони, оплату.
- `DELETE /api/package/booking/{bookingId}/share`: владелец отзывает все активные ссылки.
- Ссылки действуют до 180 дней; D1 хранит SHA-256 токена, не токен в открытом виде. GET не принимает права на изменение брони.
- «Виза готова» и «Билеты выписаны» отмечаются **только** при записанном подтверждении, никогда по самому факту наличия маршрута или бронирования.
- Страница `/s/{token}` имеет `noindex`, отображает текущий статус и разрешённые сведения, позволяет создать **свой** черновик без старой цены и без изменения исходной поездки.

- Сервер: `Backend/PackageEngine/test/booking-share.test.mjs` — 4 успешных теста (права, неразглашение, отзыв/истечение, авторизация аккаунтом).
- Веб: прошли проверки маршрутизации, MCP, локализаций, standalone Native Discovery; новый тест Smart non-stop / future-date прошёл. Все новые TS/TSX файлы прошли синтаксический разбор.

### Что пока не является полной копией iOS
Три разных входа и проверка общей стоимости существуют, но веб-ручной сценарий пока повторно использует общий генератор, а Smart не повторяет все нативные экраны и анимации SwiftUI. Поэтому **полный визуальный и функциональный 1:1-паритет iOS/Android не подтверждён**. Для Android нужен актуальный исходник; сохранённые в библиотеке архивы датированы октябрём и не отражают ноябрьскую архитектуру. Запрещено считать этап Android реализованным из наличия одного файла `assetlinks.json`.

### Критическая зависимость публикации
Workflow `deploy-package-engine.yml` разворачивает фактический backend **из `Backend/UnifiedDeploySnapshot/business-v10.tar.gz`**, а не из `Backend/PackageEngine/src`. Поэтому файлы серверной реализации, включённые в iOS-патч, **не обновят production iumrah-backend автоматически**. Перед включением публичных ссылок нужно перенести обработчик и контракт в актуальный Business/Unified Backend, запустить его тесты, D1 миграцию/создание таблицы и деплой. Без этого операции share вернут 404/503. Исходник активного Unified Backend в предоставленных архивах отсутствует; вставлять непроверенный код в несуществующую структуру нельзя.

### Android App Links
Веб-эндпоинт `/.well-known/assetlinks.json` опубликован как безопасная заготовка, **без выдуманных сертификатов**. До привязки он возвращает `[]`: ссылка при отсутствии Android-обработчика открывает веб-страницу, а не гарантированно приложение. Для нативного Android-перехода требуется актуальный Android исходник, обработчик `/s/{token}` в приложении, точный package ID и SHA-256 **Play App Signing** сертификата; затем значения `IUMRAH_ANDROID_PACKAGE_ID` и `IUMRAH_ANDROID_CERT_SHA256` в окружении веб Worker.

### Очерёдность деплоя
1. Перенести и выкатить backend share API в актуальный **единый** iumrah-backend; убедиться, что реальные визовые/билетные статусы доступны в разрешённой проекции. Проверить owner-only GET/POST/DELETE и D1 на staging.
2. Загрузить **только** `iumrah-update-20261120-public-trip-configurators.zip` в корень веб-репозитория (установщик принимает `iumrah-update*.zip`), дождаться проверок и Cloudflare Deploy.
3. Загрузить **только** `iumrah-beta-update-20261120-public-trip-links.zip` в корень iOS-репозитория, дождаться применения ZIP; затем Xcode/TestFlight.
4. После готовности Android и реальной подписи настроить App Links и проверить один и тот же URL во всех трёх клиентах.

### Требуемое живое QA перед релизом
Проверить на собственном тестовом бронировании: создание/отзыв ссылки владельцем с токеном и с привязанным аккаунтом; просмотр без входа в другом браузере; отсутствие персональных и финансовых полей в JSON и DOM; непривилегированный POST/DELETE отвергается; документы не показываются; статус visa/ticket появляется только при фактическом подтверждении; кнопка «Собрать такую же Умру» не меняет исходник и пересчитывает актуальную стоимость; iPhone 11/13 mini; Android установлен/не установлен; несколько локалей; старые ссылки `/flights/package/{id}` и `/h/*`.
