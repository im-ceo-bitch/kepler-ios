## Changes
- New official guide/team step after transfer; existing public team API is used. Default Davletbek is matched by supported name/slug aliases, only when exactly one published profile is eligible for requests on the trip dates. Sends the real member ID through the existing booking preference field. Explicit choices take priority; if unavailable, the user can choose another guide or delegate selection to iumrah. No reservation or invented member ID.
- Review changes invalidate the previous quote. Separate stable revision trigger prevents reloading SwiftUI task on its own refreshed rate tokens. Parent hotel/transfer views cannot start downstream recalculation. Repricing refreshes exact dates/occupancy in the retained hotels, deduplicates identical rate requests, and bounds concurrency to two requests. Stale results cannot overwrite current selection. Expired offer anchor is retried once. If the original room is not returned, a valid alternative with matching board/refund class requires explicit acceptance; if no suitable offer exists, choose a current rate at the same hotel or retry. No invented hotel prices.
- Planning minimum: one room through five adults, two from six through nine adults (minors do not trigger the adult-only rule), separately for each city. Automatic minimum can decrease when guests are removed; manually selected additional rooms are retained where feasible. Live supplier occupancy remains authoritative. Transfer automatically switches to a suitable existing vehicle when required; more than seven travelers need a separate transport arrangement. Train passenger counts update when selected. Prices remain server-owned. Guide is package-wide, not charged a second time.
